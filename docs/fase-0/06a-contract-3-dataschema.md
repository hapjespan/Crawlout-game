## 6. Contract 3: dataschema

Alle spelregels die getallen zijn, staan in JSON onder data/ en nergens in code. Werkstroom 4 is eigenaar van de inhoud, packages/data van de schema's en de loader.

| Bestand        | Record                             | Velden (eenheid)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| factions.json  | Factie                             | id, naam, bodyTypes\[\], startUnits\[\], startScrap, housingGrowthPerMin, safetyNet { threshold, action }, uniqueUnits\[\], uniqueBuildings\[\], specialChannel. Besluit robot-ronde (data 0.16.0, sectie 20): safetyNet is strict met action als enum (nu radiobaken_instroom) en bij die actie verplicht intervalS, maxArrivals en loadoutId (de loader levert intervalTicks); robotRules { robotsPerTechnician, technicianRoles\[\], robotPenaltyPct } verplicht bij bodyType robot in bodyTypes, anders verboden (de loader levert technicianRoles als ROLES-indices en robotPenaltyPermille). Besluit Garde-ronde (data 0.38.0 t/m 0.42.0, sectie 24 besluit 2 en 25), alle optioneel en alleen bij de Garde: veterancy { loadouts\[\], ranks\[\] { kills, hpPct, damagePct } } (ascending kills, de veteranenprogressie); fusionCores { building, scrapCost, craftS, maxStock, prereqTech\[\] } (een voltooid gebouw maakt een core tegelijk tot maxStock, een loadout met fusionCores trekt er zoveel van af bij productiestart; de loader levert milliHpPerTick-vrij, craftTicks); mapPowerArmor { loadout, respawnS, otherQualityPct } (een claimpunt van kind `powerArmor` levert de Garde-speler een frame van `loadout`; een speler van een andere factie krijgt het op otherQualityPct hp en damage, respawnS na overname of dood). Alles in de envHash. factions.json `heroId?` (data 0.42.0 held-keuze): zie 06b                                                                                                                                                                                                                                                                                                              |
| loadouts.json  | Loadout (unit = body plus loadout) | id, faction, bodyType, role, weapon, armorType, hp, damage, damageType, rangeM, speedMps, cooldownS, scrapCost, craftS, popCost, gatherAmount, gatherS, prereqTech\[\], visuals { meshSlots }. Besluit robot-ronde (data 0.16.0, sectie 20): role is scavenger, builder, militia, technician of robot (achteraan, de ROLES-indices blijven; role robot hoort bij bodyType robot en andersom); producedAt (gebouw-id waar de unit nieuw gebouwd wordt, verplicht bij bodyType robot, verboden bij human; afwezig = omscholen in de werkplaats; de loader levert −1 zonder); repair { repairRateHpPerS, rangeM, seekRangeM, targets\[\] (building, robot) } en siege { vsBuildingsDamagePct, buildingsFirst }, beide alleen bij een robot (de loader levert milliHpPerTick, rangeU, seekRangeU, vsBuildingsPermille). Welk gebouw een unit maakt staat op het loadout (producedAt), wat een gebouw kan staat op het gebouw (provides). Besluit Garde-ronde (data 0.38.0 t/m 0.42.0, sectie 24 besluit 2 en 25), alle optioneel: fusionCores (hoeveel cores een loadout met vat op productiestart aftrekt van de factie-stock, 0 zonder); overload { targets\[\], stunS, cooldownS } (de Klerk: een treffer op een vijandelijke unit van een van de `targets` loadouts stunt stunS lang, dan cooldownS tot de volgende; de loader levert stunTicks, cooldownTicks); transport { capacity, loadRangeM } (de Vertibird: tot capacity eigen menselijke units stappen in binnen loadRangeM via Load/Unload); flying (true = de unit beweegt rechtstreeks over elk terrein zonder flow field, muren of separation; voor de Vertibird). Besluit Klerk (data 0.39.0): `repair` mag ook op een technician (de Klerk kan ook repareren). Welk gebouw een unit maakt staat op het loadout (producedAt), wat een gebouw kan staat op het gebouw (provides) |
| buildings.json | Gebouw                             | id, faction, hp, armorType, scrapCost, buildS, footprint { w, h }, beds, provides\[\] (werkplaats, huisvesting, claim, turret, beacon, lab, hq, training), prereqTech\[\], visuals; besluit sprint 3, voor gebouwen met provides turret: damage, damageType, rangeM, cooldownS (verplicht bij provides turret, data 0.7.0; de loader levert damage, damageType, rangeU, cooldownTicks, 0 voor andere gebouwen). Besluit robot-ronde (data 0.16.0, sectie 20): network { requiresTech, radiusM, damagePctPerTurret, maxDamagePct } alleen bij provides turret (de loader levert radiusU en promille; null zonder). provides is in de sim een bitmasker: bit k = index k in de enum, nieuwe waarden komen achteraan, en de grens is 16 bits (was 8, alle acht bezet); de robotfabriek heeft provides \[\], de koppeling loopt via loadouts.producedAt. Besluit Garde-ronde (data 0.40.0, sectie 24 besluit 2 en 25): `armorType` kan ook `power` (power armour). De damage-matrix (06c) heeft een `power`-kolom; nieuwe waarden komen achteraan, bestaande indices blijven stabiel. Zonder Garde-factie is er geen gebouw met `armorType=power`                                                                                 |
